# Hz 网站使用与编辑手册

更新日期：2026-10-17 · 星空极简版 / 透明卡片 / Markdown 内容版

**网站：** https://3359514748.github.io/hz-blog/

**源码：** https://github.com/3359514748/hz-blog

这份说明对应当前 GitHub 版本。你可以直接在 GitHub 网页中编辑，不需要先安装开发工具。进入任一内容栏目，页面底部的“使用说明”也能打开本手册；首页仅保留导航与中央短句。也可直接打开 https://3359514748.github.io/hz-blog/#guide 。

## 一、先掌握三个位置

| 想修改什么 | 编辑哪个文件 | 是否需要改网页代码 |
| --- | --- | --- |
| 网站介绍、首页标题、顶部栏目名称与顺序 | `site.config.json` | 不需要 |
| 文章标题、日期、摘要、标签、所属栏目、排列顺序 | `content/index.json` | 不需要 |
| 文章或项目的正文 | `content/posts/文章文件名.md` | 不需要 |
| 图片 | 上传到 `assets/` | 通常不需要 |
| 配色、字号、间距 | `style.css` | 需要改样式代码 |
| 星星数量、亮度、移动速度 | `site.config.json` 中的 `background` | 不需要 |
| 随鼠标运动的背景算法 | `stars.js` | 需要改交互代码 |
| 浏览器标签页图标 | `assets/favicon.svg` | 需要替换图片或编辑 SVG |

这里的“文章”也包括知识笔记、项目介绍和公开短想法：它们共用同一套 Markdown 内容系统。

**最重要的规则：正文文件与内容索引需要对应。** 单独上传 `.md` 文件不会自动加入列表；还要在 `content/index.json` 中增加一条记录。已有文章只改正文时，无需重复增加索引。

## 二、最快上手：修改一篇已有文章

1. 打开上面的 GitHub 源码仓库。
2. 进入 `content` → `posts`，选择一篇 `.md` 文件，例如 `garden.md`。
3. 点击文件页的编辑按钮（铅笔 / Edit this file）。
4. 像普通文本一样修改正文，Markdown 写法见后文。
5. 点击 **Commit changes**，填写简短说明，例如“更新知识系统笔记”，提交到 `main`。
6. 打开仓库 **Actions**，等待相应的 `pages build and deployment` 显示绿色成功状态。
7. 刷新网站，打开这篇文章查看。

如果你也改了标题、摘要、日期或标签，再编辑 `content/index.json` 对应的记录。

### 把示例换成自己的真实内容

现有条目保留了 `"sample": true`，所以页面会显示“示例”及说明文字。替换成你的真实内容后，把那一条的 `sample` 改为 `false`，并修改标题、摘要和正文。不要只去掉标记而保留虚构经历或未经确认的成果。

## 三、新增一篇文章：完整步骤

### 第一步：创建正文

在仓库页面使用 **Add file → Create new file**，文件名填写：

```text
content/posts/my-first-post.md
```

正文可以从下面开始：

```markdown
这是一篇关于我的观察与实践的记录。

## 为什么开始

说明我遇到了什么问题，以及为什么值得记录。

## 我的尝试

- 第一个做法
- 遇到的问题
- 下一次想调整的地方

## 仍待回答的问题

把尚未想清楚的部分留在这里。
```

提交文件。文件名建议使用英文小写、数字与连字符，不要使用空格或中文文件名。

### 第二步：在索引中登记

打开 `content/index.json`，在最外层数组中增加以下对象。它与前后对象之间要有逗号：

```json
{
  "id": "my-first-post",
  "section": "blog",
  "title": "我的第一篇文章",
  "summary": "从一次具体的观察出发，记录问题、尝试与反思。",
  "date": "2026-10-17",
  "tags": ["日常思考", "实践"],
  "file": "content/posts/my-first-post.md",
  "sample": false,
  "featured": false,
  "published": true
}
```

提交索引后，等待 Actions 发布完成，文章就会出现在“博客”栏目中，相关标签会自动成为筛选按钮，搜索也会包含这篇文章。

你也可以先改索引再上传正文，但中间版本可能出现“正文不存在”。推荐先提交正文，再登记索引；如果使用 GitHub Desktop，可以在同一次提交中加入两者。

### 第三步：检查真实链接

在网站点开文章，浏览器地址会变成：

```text
https://3359514748.github.io/hz-blog/#read/my-first-post
```

“复制文章链接”可分享该地址。它支持刷新、直接打开和浏览器后退；因为是静态网站内的片段链接，尚不等于独立生成的 HTML 文章页面，也没有为每篇文章生成搜索引擎摘要或社交分享图。

## 四、内容索引的字段说明

`content/index.json` 是一个数组，当前示例内容可直接复制作为范本。

| 字段 | 必填 | 用途与限制 |
| --- | --- | --- |
| `id` | 是 | 内容的稳定标识，全站唯一；只用英文小写、数字和连字符，例如 `reading-notes-01`。已分享链接依赖它，尽量不要改。 |
| `section` | 是 | 所属栏目的 `id`，必须与配置中的栏目对应；例如 `blog`。 |
| `title` | 是 | 页面和列表中的文章标题。 |
| `summary` | 建议 | 列表摘要和文章导语。 |
| `date` | 建议 | 显示日期，建议 `YYYY-MM-DD`；留空时显示“示例内容”或“未标日期”。日期不控制排序。 |
| `tags` | 否 | 字符串数组；标签筛选与搜索自动读取它。 |
| `file` | 是 | 正文路径，必须是 `content/posts/英文文件名.md`。 |
| `sample` | 否 | `true` 显示示例提示；真实内容使用 `false`。 |
| `featured` | 否 | `true` 显示“精选”标记；不自动改变排序。 |
| `published` | 否 | `false` 时不加入网站列表、搜索或阅读路由；省略或 `true` 为显示。 |
| `order` | 否 | 数字，越小越靠前；建议不使用时按数组顺序排列。 |
| `status` | 否 | 简介卡片底部文字，例如“进行中”“已完成”“概念示例”。 |
| `url` | 否 | 填写完整的 `https://` 或 `http://` 地址后，简介卡片、想法和搜索结果可在新标签页打开该链接；省略则打开站内正文。`file` 仍需填写，以保留站内正文与稳定链接。其他协议或无效地址会退回站内正文。 |

### 文章与卡片排序

- 默认按索引数组中的顺序展示，**不是自动按日期排序**。
- 把一条记录移到前面，就会更靠前。推荐所有条目都不写 `order`，只调整数组顺序。
- 若使用 `order`，建议给所有条目设置它，避免显式数值与默认数组序号混排。
- 首页只显示中央短句，不再展示文章列表或项目预览。
- `featured` 只添加标记；想让内容在栏目中靠前，请调整顺序。
- 想法堆栈也按此顺序切换，当前卡片可点击阅读；下方箭头、键盘方向键和滚轮均可切换。

### 删除、隐藏和移动内容

- **隐藏：** 把条目的 `published` 改成 `false`，或从索引中移除该对象。
- **删除：** 从索引移除记录，再删除对应 Markdown 和不再使用的图片。
- **移动栏目：** 把 `section` 改成目标栏目的 `id`。
- **新增标签：** 直接在 `tags` 中增加文字，不用改页面代码。

隐藏是展示设置，不是访问权限。公开仓库中的 Markdown、附件和提交历史仍可能被直接访问。私密文章不要上传到这个公开仓库。

## 五、修改顶部栏目

打开 [`site.config.json`](https://github.com/3359514748/hz-blog/blob/main/site.config.json)。其中的 `sections` 控制顶部导航。

一条栏目配置如下：

```json
{
  "id": "blog",
  "label": "Log",
  "title": "博客",
  "eyebrow": "WRITING",
  "description": "把值得展开的思考，写成文章。",
  "layout": "cards"
}
```

| 字段 | 用途 |
| --- | --- |
| `id` | 栏目稳定标识；内容索引的 `section` 引用它。全站唯一，只用英文小写、数字、连字符。 |
| `label` | 顶部菜单名称，当前为简短英文：Log、KB、Lab、Ideas。可以自行更名。 |
| `title` | 栏目内显示的标题，例如“博客”；省略时使用 label。 |
| `eyebrow` | 栏目标题上方的小字，可自行更换。 |
| `description` | 栏目介绍。 |
| `layout` | `cards` 为并排透明简介卡片（手机单列），`stack` 为滚轮切换的立体透明堆栈，`list` 为简洁列表。 |
| `enabled` | 可选；设为 `false` 隐藏栏目。至少保留一个可见栏目。 |

### 常见修改

**把“博客”改名为“随笔”：** 把 `title` 改成“随笔”，保留 `id: "blog"`；导航仍显示 Log。若要改导航，再修改 `label`。已有文章无需修改。

**调整顶部顺序：** 移动 `sections` 数组中整个栏目对象的位置。首页顶部导航的顺序也会随之调整。

**新增“阅读”栏目：** 在 `sections` 中增加：

```json
{
  "id": "reading",
  "label": "Read",
  "title": "阅读",
  "eyebrow": "READING",
  "description": "读过的内容，以及留下的问题。",
  "layout": "list"
}
```

再在内容索引中添加 `"section": "reading"` 的文章，它们就会进入新栏目。无需在 `app.js` 增加页面。

**更换展示方式：** 博客、知识库和项目目前都使用 `cards`；想法使用 `stack`。修改 layout 即可切换，新建栏目也能任选一种。

**隐藏栏目：** 给栏目增加 `"enabled": false`。该栏目内容也不再进入本站列表和搜索；文件仍是公开的。

不要使用以下保留词作为栏目 id：`home`、`read`、`section`、`guide`、`main`。`stack` 布局的下方带有本机草稿面板；它与公开 Markdown 内容相互独立。更换栏目 id 时，记得同时修改内容索引的 section。

## 六、修改首页文字与图标

配置文件的其他字段：

| 字段 | 页面位置 |
| --- | --- |
| `name` | 网站名称、浏览器标题和页脚。 |
| `tagline` | 保留的旧配置字段，当前极简首页不显示。 |
| `heroLines` | 首页中央大标题，一到三行字符串，统一使用银白色。 |
| `description` | 首页大标题下方介绍。 |
| `intro` | 浏览器标题和内容页页脚短句。 |
| `footer` | 页脚右侧英文文字。 |

例如：

```json
"heroLines": ["记录日常，", "整理自己的世界。"],
"description": "这里记录我的写作、阅读和项目。"
```

这只是配置片段，不是完整 JSON 文件；请在已有文件里修改对应字段。

当前 Hz 图标保留了你喜欢的斜体字与细边框，顶部使用文字绘制，浏览器图标使用 `assets/favicon.svg`。`name` 字段不会自动重绘 Hz 标志。如果以后要更换品牌标志，修改顶部 `.brand-icon` 的文字或结构，并替换 favicon。

少量界面辅助文字、动效按钮和模板文字仍在 `app.js`、`stars.js` 或 `index.html` 中。日常维护栏目与文章无需修改它们。Home 是固定的首页入口，其文字在 app.js 的导航初始化处。

## 七、Markdown 常用写法

文章页已从索引显示大标题，正文通常直接从引言或二级标题开始，不必重复写一级标题。

### 标题、强调和列表

```markdown
## 二级标题

### 三级标题

普通正文，**强调文字**，*斜体文字*。

- 一个要点
- 另一个要点

1. 第一步
2. 第二步

> 这是一段引用。引用他人观点时应补充出处。
```

### 链接和站内引用

```markdown
[外部资料](https://example.com)

[另一篇文章](#read/garden)

[知识库栏目](#section/knowledge)
```

### 图片

1. 在 GitHub 打开 `assets/`，选择 **Add file → Upload files** 上传图片。
2. 记住文件名，例如 `reading-desk.jpg`。
3. 在正文里写：

```markdown
![书桌上的阅读记录](assets/reading-desk.jpg)
```

图片路径从网站根目录计算，不是从 Markdown 所在文件夹计算。因此统一写 `assets/文件名`。不要写 `C:\...` 本地路径，也不要以 `/assets/` 开头，否则部署到 `/hz-blog/` 这种子目录后可能失效。大小写必须与真实文件名一致。

### 代码、表格和分隔线

行内代码用单个反引号包住；多行代码用三个反引号起止，可在起始行后写语言名。当前支持代码块排版，不提供额外的语法高亮。

```markdown
| 项目 | 记录 |
| --- | --- |
| 观察 | 发生了什么 |
| 下一步 | 可以尝试什么 |

---
```

正文支持普通 Markdown 和表格。为了避免正文注入网页脚本，原始 HTML 被当作文字显示。没有启用数学公式、Mermaid、任务复选框插件或可执行脚本；不要依赖它们生成交互功能。

当前没有 YAML front matter 自动解析。标题、日期和标签都应写进索引，不要把 `--- title: ... ---` 当作自动生效的元数据。

## 八、JSON 最容易出错的地方

配置和索引使用 JSON，规则比普通文字严格：

- 字段名与字符串使用英文双引号 `"`，不能使用中文引号。
- 数组使用方括号，对象使用大括号。
- 同一对象的字段之间、数组里的对象之间使用英文逗号。
- 最后一项后面不要加逗号。
- `true` 和 `false` 不带引号。
- JSON 不支持 `//` 注释。不要把本手册的解释行粘进配置。
- 字符串里需要双引号时，写成 `\"`，例如 `"title": "关于\"记录\"的思考"`。

在点击提交前可以使用 GitHub 的预览或本地编辑器检查格式。仓库附带可选命令 `node tools/check-content.cjs`，会检查 JSON、栏目引用、重复 id、Markdown 文件是否存在，以及当前允许的正文路径。它是内容检查工具，不会自动帮你发布。

## 九、在不同设备上更新

用手机或另一台电脑登录你的 GitHub 账号，打开同一仓库即可编辑；访问公开网站不需要登录。

```text
编辑 Markdown / 配置 / 索引
    ↓
Commit changes 到 main
    ↓
GitHub Actions：pages build and deployment
    ↓
绿色成功状态
    ↓
刷新同一个公开网址
```

发布通常需要等待，具体耗时以 GitHub 的任务状态为准。**保存本地文件、保存编辑草稿或只打开预览，都不等于提交到了线上。**

### 维护方式选择

- 偶尔更新：直接使用 GitHub 网页编辑。
- 多文件更新：使用 GitHub Desktop，在一次提交中加入 Markdown、索引与图片，避免中间状态。
- 不想处理文件结构：把文章发到本对话，明确“更新 GitHub 版 Hz”，我也可以协助处理。

本网站没有可直接写入 GitHub 的登录后台。不要把 GitHub Token 放进公开网页脚本来实现在线发布，这会暴露仓库写权限。若以后需要所见即所得后台，应单独设计登录及安全的保存流程。

## 十、本机随记、导出和动效

想法栏使用立体透明卡片堆栈。鼠标放在卡片区域后滚动滚轮可切换，触屏可上下滑，也可点击下方 ↑ / ↓ 或使用键盘上下方向键。点击旁边卡片会先将它移到中央，点击中央卡片才打开正文。到第一条或最后一条后继续向外滚动，可以正常滚动整页。

向下滚动到堆栈下方，可以找到“随手记一条”本机草稿面板。

- 保存后仅存在当前浏览器、当前域名下。
- 它不会加入公开索引，不会提交到 GitHub，也不会跨设备同步。
- 可点击“导出草稿”，得到 Markdown 文件。之后手动整理正文并登记索引，才会成为公开内容。
- 清理浏览器数据可能丢失草稿；重要内容请导出或另存。
- GitHub 旧版草稿使用相同本机存储键，原域名内的旧记录可继续显示；Sites 域名或其他浏览器里的记录不会自动迁移。

右上角暂停按钮控制背景动效，并在当前浏览器记住你的选择。系统设置“减少动态效果”且未手动选择时，默认暂停。触屏设备没有鼠标悬停，背景保留缓慢变化；切换到后台时动画停止计算。暗色设计不等于医学意义的护眼保证，可按实际感受调整亮度或暂停。

### 调整星空（不需要改代码）

在 site.config.json 中修改 background：

```json
"background": {
  "whiteStars": 1500,
  "blueStars": 1000,
  "brightness": 1,
  "speed": 0.35
}
```

- whiteStars：白色星点的基准数量，允许 100–4000；想更多白亮点，优先提高此项。
- blueStars：蓝色细碎星尘的基准数量，允许 0–4000。
- brightness：亮度系数，允许 0.2–1.5；默认 1，可尝试 0.75 或 1.15。
- speed：缓慢漂移速度，允许 0–2；设为 0 停止自动漂移，鼠标视差仍保留。完全暂停请点击顶部暂停按钮。

数量会按屏幕面积调整，手机约为同面积基准的 45%，以减少绘制负担。阅读文章时会自动降低背景亮度。增加数量和亮度会影响耗电与观感，建议每次小幅调整；是否舒适以你的实际体验为准。

玻璃卡片的透明度、边框和间距在 style.css 的 .project-card 中；立体想法堆栈的外观在 .idea-card 与 .idea-inner 中。鼠标视差、星点和短尾迹在 stars.js 中实现；仅复制 CSS 不会产生完整星空动效。

## 十一、常见故障

| 现象 | 优先检查 |
| --- | --- |
| 提示“这页暂时没能打开” | 阅读提示中具体文件名，检查 JSON 是否有错、文件是否上传。 |
| 新文章不在列表里 | 索引是否登记、`section` 是否匹配、`published` 是否为 false、栏目是否被隐藏。 |
| 能看到标题，点开正文失败 | `file` 路径、大小写和 Markdown 文件名是否一致；正文是否已提交。 |
| 新标签没显示 | `tags` 是否为字符串数组，文章是否属于当前栏目。 |
| 图片加载失败 | 路径应为 `assets/文件名`，检查文件名和大小写；不要用本地路径。 |
| 修改后还是旧版 | 确认提交到 main、对应 Actions 成功，再刷新；可强制刷新或换无痕窗口检查。 |
| 某个栏目消失 | 检查 `enabled`、栏目 id 和配置格式。 |
| 旧文章分享链接失效 | 是否改了文章 id、移除了记录或设置为不发布。 |
| 搜索不到正文中的词 | 当前搜索范围是标题、摘要和标签，不做正文全文检索。 |
| 手机打不开但电脑可以 | 用同一完整网址检查；比较网络对 GitHub Pages 的连通性，不要使用 localhost 地址。 |

### 如何恢复误改

GitHub 有提交历史。打开出错文件的 History，找到修改前的版本，复制正确内容再提交。不要在不清楚影响时强制重置整个仓库。GitHub 历史也意味着删掉公开文章并不一定抹去已公开的旧内容。

## 十二、备份与本地预览

备份：在仓库 **Code → Download ZIP** 下载源码，包含配置、正文和图片；本机草稿需要单独导出。

可选本地预览：如果电脑已安装 Node.js，在项目根目录运行：

```text
node tools/preview.cjs
```

然后打开它输出的 `http://127.0.0.1:49354`。预览只绑定本机，没有上传接口；结束时在终端按 Ctrl+C。也可以使用其他静态 HTTP 服务器。**不要仅双击 index.html**：浏览器在 `file://` 下可能阻止读取配置和正文文件。

本地预览适合提交前检查；其他网络和设备仍使用正式的 GitHub Pages 网址。
